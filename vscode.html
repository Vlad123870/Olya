01
ОСНОВА

Интерфейс VS Code и правильная работа с папками

Главное отличие VS Code от Visual Studio в ежедневной работе состоит в том, что VS Code воспринимается прежде всего как редактор с рабочей папкой. Ты не обязан начинать с большого решения и шаблона проекта: обычно достаточно открыть папку, в которой находятся файлы программы.

ExplorerЛевая панель с файлами и папками рабочей области. Отсюда создают, открывают, переименовывают и перемещают файлы.
EditorЦентральная область, где пишется код. Можно открыть несколько файлов во вкладках и разделить окно редактора на несколько областей.
SearchПоиск не только в текущем файле, но и по всей открытой папке. Очень полезен, когда проект разрастается.
Run and DebugПанель запуска и отладки. Здесь появляются конфигурации, кнопки запуска и инструменты для просмотра состояния программы.
ExtensionsКаталог установленных и доступных расширений. Языковые возможности VS Code часто добавляются именно отсюда.
Source ControlВстроенный интерфейс Git. Он показывает изменённые файлы и позволяет выполнять базовые операции Git без постоянного переключения в терминал.
TerminalПолноценный встроенный терминал. В нём можно запускать Python, pip, g++, git и другие команды так же, как в обычной консоли.
Status BarНижняя строка состояния. Для Python здесь особенно важен выбранный интерпретатор; для C++ — информация о файле и контексте работы.

Почему лучше открывать папку проекта

Представь проект calculator:

📁 calculator
📄 main.py
📄 utils.py
📁 .venv
📄 README.md

Если открыть именно папку calculator, VS Code понимает её как workspace: поиск, терминал, Python environment, диагностика и конфигурации начинают работать в контексте этого проекта. Для Python документация VS Code отдельно отмечает, что выбранное окружение используется для IntelliSense, автодополнения, линтинга, форматирования, запуска и отладки.

Что делать каждый раз

File → Open Folder → выбрать папку проекта → открыть нужный .py или .cpp → проверить инструменты → писать код.

Чего лучше не делать

Не создавай десятки файлов в одной случайной папке «Загрузки». Для каждого отдельного проекта лучше иметь свою директорию с понятным названием.

02
РАСШИРЕНИЯ

Что установить для Python и C++

Открывай Extensions на боковой панели или нажимай Ctrl + Shift + X. Расширения добавляют языковую поддержку, IntelliSense, запуск, отладку и другие возможности.

PYTHON

Python — Microsoft

Основное расширение для Python. Оно добавляет интеграцию с интерпретаторами, запуск файлов, отладку, работу с окружениями и другие функции языка.

Pylance поставляется вместе с Python extension как язык поддержки Python и отвечает за IntelliSense, навигацию и диагностику.
PYTHON DEBUG

Python Debugger

Отдельный компонент для отладки Python. В актуальном VS Code он устанавливается вместе с Python extension, поэтому вручную искать его обычно не нужно.

Через Debugger можно ставить breakpoint, смотреть переменные и выполнять программу по шагам.
C / C++

C/C++ — Microsoft

Добавляет подсветку синтаксиса, IntelliSense, диагностику и поддержку отладки C/C++.

Важно: расширение не содержит сам компилятор. Компилятор и отладчик должны быть установлены отдельно или уже присутствовать в системе.
Для Оли: если основной язык — Python, начни с Python extension. C/C++ extension устанавливай только тогда, когда реально понадобится C++.
03
PYTHON · СТАРТ

Python: от пустой папки до запуска программы

VS Code сам по себе не является интерпретатором Python. Для запуска кода на компьютере должен быть установлен Python interpreter, а расширение Python связывает этот интерпретатор с VS Code.

1Открой папку

Через File → Open Folder открой отдельную папку проекта, например python-lessons.

2Создай файл

В Explorer создай main.py. Расширение .py позволит VS Code распознать язык Python.

3Выбери interpreter

Используй команду Python: Select Interpreter или нажми на выбранную версию Python в Status Bar.

4Напиши код

Например, print("Привет, Оля!"). Если IntelliSense работает, VS Code будет помогать с синтаксисом и названиями.

5Запусти

Используй кнопку запуска файла или команду Python: Run Python File in Terminal.

main.py
name = "Оля"
print(f"Привет, {name}!")

for i in range(3):
    print(i)

Если VS Code предлагает несколько Python

Это нормально. На компьютере могут существовать системный Python, несколько версий Python и виртуальные окружения. Выбери тот interpreter, который относится к текущему проекту.

Почему interpreter так важен

Именно выбранное окружение определяет, где VS Code ищет Python и установленные пакеты, а также какой Python используется при запуске и отладке.

04
PYTHON · ОКРУЖЕНИЯ

Virtual Environment и pip

Когда проект использует библиотеки, удобнее держать их в отдельном виртуальном окружении. Тогда зависимости одного проекта не смешиваются с зависимостями другого.

Создание окружения

python -m venv .venv

После выполнения команды в проекте появляется папка .venv. Саму папку обычно не редактируют вручную: это окружение с отдельным Python и установленными пакетами.

Выбор окружения в VS Code

После создания .venv выполни Python: Select Interpreter и выбери интерпретатор из этого окружения. VS Code умеет автоматически обнаруживать локальные virtual environments, включая .venv и venv.

Установка библиотеки

python -m pip install requests

Формат python -m pip удобен тем, что запускает pip через тот Python, который вызван командой. Это помогает уменьшить путаницу, когда на компьютере установлено несколько Python.

Проверка установленного пакета

python -m pip show requests

Если VS Code показывает ошибку Import ... could not be resolved, первым делом проверь, что пакет установлен именно в выбранном interpreter. Документация VS Code рекомендует в таких ситуациях проверить выбранное окружение и при необходимости установить пакет в него.

Простое правило: открыл другой проект → проверь interpreter → затем устанавливай библиотеки. Очень много «магических» ошибок Python в VS Code на практике связано именно с тем, что код запускается другим Python, чем тот, куда ставились пакеты.
05
PYTHON · РЕДАКТОР

Что VS Code делает за тебя при написании Python

После установки Python extension и выбора interpreter редактор становится значительно умнее обычного текстового редактора. Большая часть этих возможностей связана с IntelliSense и Pylance.

  • Автодополнение. VS Code предлагает функции, методы, переменные и параметры по мере ввода.
  • Подсказка по параметрам. При вызове функции редактор может показать её сигнатуру и типы.
  • Переход к определению. Можно быстро перейти к месту, где объявлена функция, класс или переменная.
  • Ошибки прямо в коде. Подозрительные места подчёркиваются, а в панели Problems можно увидеть диагностику.
  • Quick Fix. Для части проблем появляется значок «лампочки» с вариантами исправления.
  • Переименование. При структурированном проекте VS Code может помочь заменить имя символа по проекту.
  • Форматирование. Код можно привести к единому стилю с помощью команды форматирования.
    • Важно: подчёркивание не всегда означает, что программа точно не запустится. Это может быть предупреждение анализатора. Но если VS Code сообщает, что импорт не найден, сначала проверь выбранное окружение и наличие пакета.
    06
    RUN & DEBUG

    Запуск и Debugger: как перестать отлаживать код через бесконечные print()

    Debugger нужен тогда, когда тебе важно увидеть, что происходит внутри программы в конкретный момент. Вместо того чтобы добавлять десятки временных print(), можно остановить выполнение на нужной строке и посмотреть значения переменных.

    1Breakpoint

    Нажми F9 или кликни слева от строки. Это инструкция: «если выполнение дойдёт сюда — остановись».

    2Start Debugging

    Нажми F5 или запусти отладку из панели Run and Debug.

    3Посмотри состояние

    Когда программа остановилась, смотри значения переменных, стек вызовов и текущую строку.

    4Шагай

    Переходи по строкам и наблюдай, как меняется состояние программы.

    5Продолжай

    Продолжи выполнение и посмотри, что происходит дальше.

    Когда использовать F5

    Когда ты хочешь именно исследовать программу: выяснить, почему условие сработало, откуда взялось значение или в какой функции произошёл неожиданный результат.

    Когда достаточно обычного запуска

    Когда программа небольшая и ты уже понимаешь её поведение. Для быстрой проверки кода не обязательно каждый раз запускать полноценную отладочную сессию.

    Пример для отладки
    a = 10
b = 0

if b == 0:
    result = "деление невозможно"
else:
    result = a / b

print(result)

    Поставь breakpoint на строку if b == 0:, запусти отладку и посмотри, какое значение у b. Такой подход постепенно учит не просто «видеть ошибку», а понимать путь исполнения программы.

    Для Python актуальная документация VS Code указывает, что Python Debugger позволяет ставить breakpoints, проверять переменные и пошагово выполнять код. Конфигурации отладки при необходимости сохраняются в .vscode/launch.json.

    07
    C++ · НАСТРОЙКА

    C++ в VS Code: что нужно кроме расширения

    Здесь есть важный момент, который часто путают новички: C/C++ extension — это не компилятор. Расширение даёт VS Code поддержку языка, IntelliSense и интеграцию с отладкой, но сам C++-код должен компилироваться отдельным toolchain. На Windows это может быть, например, MSVC или MinGW.

    VS CodeРедактор и интерфейс разработки
    C/C++ extensionЯзыковая поддержка, IntelliSense, диагностика, debug integration
    CompilerПревращает исходный код C++ в исполняемую программу
    DebuggerПозволяет пошагово исследовать работающую программу

    Сначала проверяем, есть ли компилятор

    Открой Terminal → New Terminal и выполни:

    g++ --version

    Если терминал показывает версию, значит команда g++ доступна через системный PATH. Если система пишет, что команда не найдена, расширение C/C++ само по себе эту проблему не исправит: сначала нужно установить или подключить toolchain.

    Практический совет: если C++ нужен только иногда, не запутывайся в десятке расширений. Достаточно понять три сущности: VS Code → C/C++ extension → compiler/debugger.
    08
    C++ · РАБОТА

    C++: написать → собрать → запустить → отладить

    После того как g++ доступен, базовый цикл работы можно выполнять прямо из встроенного терминала.

    1. Создай файл

    Например, main.cpp:

    #include <iostream>

int main() {
    int a = 5;
    int b = 7;
    std::cout << a + b << '\\n';
    return 0;
}

    2. Скомпилируй

    g++ main.cpp -o main

    Здесь main.cpp — исходный файл, а -o main говорит компилятору, как назвать выходной файл.

    3. Запусти

    main.exe

    В Windows это типичный вариант, когда получился исполняемый файл main.exe.

    4. Отлаживай

    Для полноценного F5/debug workflow VS Code может использовать файл .vscode/launch.json. В зависимости от выбранного toolchain конфигурация отладки отличается. Например, для MinGW документация Microsoft показывает конфигурацию с g++.exe и при необходимости настройкой пути к gdb.exe.

    Когда достаточно терминала

    Для простых университетских задач: одна программа, один файл, компиляция одной командой. Это часто самый прозрачный способ понять, что именно происходит.

    Когда удобнее Run and Debug

    Когда появляются несколько файлов, breakpoint, сложные вызовы функций и необходимость наблюдать значения переменных.

    09
    ТЕРМИНАЛ

    Встроенный терминал: твой главный инструмент рядом с кодом

    VS Code содержит полноценный integrated terminal. Он стартует в контексте рабочей папки и умеет выполнять те же команды, что и обычный терминал. Открыть его можно через Terminal → New Terminal или сочетание Ctrl + `.

    Ctrl + `показать или скрыть терминал
    Ctrl + Shift + `создать новый терминал
    pwdпосмотреть текущую папку в Bash/Unix-подобном терминале
    cd папкаперейти в другую директорию
    python main.pyзапустить Python-файл
    g++ main.cpp -o mainскомпилировать C++-файл

    Как понять, где ты находишься

    Если терминал неожиданно говорит, что файл не найден, часто проблема не в коде, а в текущей папке. Проверь путь к файлу в Explorer и сравни его с текущей директорией терминала.

    Терминал и Git Bash

    Поскольку на сайте уже есть отдельный справочник по Git Bash, удобно воспринимать встроенный терминал VS Code как место, где можно применять эти команды прямо рядом с проектом. Сам VS Code не меняет правила Git Bash: он просто предоставляет оболочке встроенное окно.

    11
    WORKFLOW

    Как реально работать в VS Code каждый день

    01Открой папку проектаНе начинай работу с отдельного файла, если у тебя уже есть структура проекта.
    02Проверь инструментPython: выбран interpreter. C++: доступен compiler.
    03Пиши небольшой кусокНе набирай всю программу на 300 строк, не проверяя промежуточный результат.
    04Запускай частоОшибку на двух строках легче найти, чем ошибку после часа непрерывной работы.
    05Используй DebuggerЕсли программа делает не то — смотри значения, а не только перечитывай код.
    06Читай ProblemsСмотри не только на красное подчёркивание, но и на точный текст сообщения.
    07Форматируй кодЕдиный стиль уменьшает количество визуальных ошибок и облегчает чтение.
    08Сохраняй проект аккуратноОдна задача — одна понятная папка. Не складывай всё в один каталог.
    Хорошая привычка: когда что-то не работает, не начинай хаотично нажимать кнопки. Сначала сформулируй симптом одной фразой — например, «Python запускается другим interpreter». После этого уже проверяй конкретный слой системы.
